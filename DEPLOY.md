# Облачный пилот

## Первый запуск: только предпросмотр

1. Создать отдельный Railway service из этого репозитория (Dockerfile).
2. Подключить Volume к `/data`, оставить один экземпляр. Публичный домен не нужен.
3. Установить переменные сервиса:

| Переменная | Значение |
|---|---|
| RUN_MODE | preview |
| OUTPUT_DIR | /data |
| IMAP_HOST | imap.ya.ru (официальный адрес для подключения из-за границы) |
| IMAP_USER | адрес ящика |
| IMAP_PASSWORD | пароль приложения Почта; вводить в Railway Variables |
| REPORT_START | начало периода YYYY-MM-DD |
| REPORT_END | конец периода YYYY-MM-DD |
| BOT_CONFIG_JSON | JSON ниже с реальными значениями |

```json
{
  "sender": "approver@example.com",
  "mailbox": "Exact IMAP folder name",
  "project_mailbox": true,
  "parent_mailboxes": ["Exact IMAP folder name"],
  "attachment_senders": [],
  "amount_cells": {},
  "disk_folders": {}
}
```

В mailbox указать точное имя, возвращаемое IMAP, включая пробелы и `|`. project_mailbox=true допускает отсутствие названия проекта в теме, поэтому папка должна принадлежать одному проекту. Просматривается эта папка; подпапки автоматически не обходятся. parent_mailboxes используется только для поиска точного исходного письма согласования.

Для первого запуска IMAP достаточно: токены Диска и Telegram не нужны. Запустить deploy. Успех — `Preview complete: documents=... review=...` в логах. После успешного прохода процесс завершается; это нормальное поведение preview, не постоянный сервер. При ошибке Railway повторит запуск согласно railway.json, максимум три раза.

Результаты лежат на Volume: `/data/report.json`, `/data/report.txt`. Чтение через Railway SSH: `cat /data/report.json` (только в приватном сеансе; если preview остановлен, для просмотра Volume потребуется запущенный процесс сервиса). В логах только счётчики, без переписки. Приложение не предоставляет публичный endpoint для скачивания отчётов.

## Подключение Диска после проверки правил

Добавить `YANDEX_DISK_TOKEN` с правами чтения и записи Диска. Почтовый пароль не даёт доступа к API Диска.

В `disk_folders` задать проверенные полные пути, например:

```json
{"смета:337":"disk:/Example/337/1. согл","акт:253":"disk:/Example/253/3. исп (акт)"}
```

Это примеры, не реальные пути. Папки должны существовать. Нет автоматического создания папок и угадывания соответствий. Отсутствующий путь означает пропуск загрузки документа.

Режим preview никогда не загружает файлы. После проверки отдельный запуск `python bot.py --start YYYY-MM-DD --end YYYY-MM-DD --output /data --publish` загружает согласованные документы и отправляет сводку в Telegram; ему также нужны TELEGRAM_TOKEN, TELEGRAM_CHAT_ID, TELEGRAM_THREAD_ID. `--publish --no-disk` отправляет только сводку. Не выполнять publish до проверки получателей и путей.

Байты вложений остаются в RAM, загрузка выполняется HTTPS PUT. OAuth-токен отправляется только API Диска, не upload URL. Файлы не перезаписываются; одинаковый файл с тем же именем/размером/хешем повторно не загружается. После загрузки проверяется размер и SHA-256 (MD5, если SHA-256 отсутствует). Неопределённая загрузка считается ошибкой. При повторном запуске наличие файла проверяется заново.

## Постоянная работа

RUN_MODE=telegram включает прежний worker. Нужны TELEGRAM_TOKEN, TELEGRAM_OWNER_ID, TELEGRAM_CHAT_ID, TELEGRAM_THREAD_ID. Единственный экземпляр, без Telegram webhook. Команда `/report` отправляет сводку, но не пишет на Диск. Расписание и команда автоматической загрузки пока не включены.

В исходный код, Git и build context не помещать пароли, реальные конфигурации, отчёты и письма. Docker ещё требуется проверить реальной сборкой Railway. Для первого рабочего запуска использовать короткий период: весь набор писем и связанные исходные письма разбираются в памяти.
