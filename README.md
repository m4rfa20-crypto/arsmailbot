# arsmailbot

Прототип бота согласований: IMAP → XLSX → сводка в Telegram. Python 3.12+, без LLM.

## Статус

Код прошёл 21 локальный тест. Реальные IMAP, Telegram, Диск и сборка Docker ещё не проверены. Это пилот: суммы и правила согласования требуют сверки на реальных документах.

## Возможности

- Период включительно, московское время, заданный отправитель согласования.
- Фильтр проекта НОВЬ/НОВИ; для отдельной проектной папки — project_mailbox=true.
- Явное согласование в новой части plain-text письма; цитаты, отрицания и условия исключаются по консервативным правилам. HTML-only письма требуют ручной проверки.
- XLSX до 20 МБ; номер из имени, слово АКТ определяет тип акта, числовое имя без него считается сметой. Это соглашение проверяется на пилоте.
- Суммы из настроенных итоговых ячеек, с учётом кеша формул; неизвестная сумма не заменяется нулём. Валюта пилота — RUB.
- Повторные байты вложений не увеличивают итог; разные версии одного номера исключаются из суммы.
- Если в согласовании нет вложения, акт берётся из непосредственного исходного письма через In-Reply-To либо последний References. Совпадения темы недостаточно. Исходное письмо может предшествовать отчётному периоду.
- При нескольких актах требуется однозначный номер в новом тексте согласования; неопределённые случаи направляются на проверку.
- Реестр сохраняет Message-ID согласования и источника вложения. Ссылка на письмо — поиск по теме, не точная ссылка.
- Telegram /status и /report ГГГГ-ММ-ДД ГГГГ-ММ-ДД. Команды принимает только заданный пользователь в заданной теме.

## Railway

Создать сервис из этого репозитория. Dockerfile запускает worker.py. Один экземпляр, Volume /data, публичный домен не нужен. Для токена Telegram не должен быть настроен webhook, второй polling-процесс с этим токеном недопустим.

Variables:

- TELEGRAM_TOKEN — токен отдельного бота.
- TELEGRAM_OWNER_ID — числовой ID разрешённого пользователя.
- TELEGRAM_CHAT_ID, TELEGRAM_THREAD_ID — группа и тема.
- IMAP_USER, IMAP_PASSWORD — адрес и пароль приложения.
- IMAP_HOST — сервер IMAP; по умолчанию imap.yandex.ru:993 TLS.
- OUTPUT_DIR=/data.
- BOT_CONFIG_JSON — конфигурация (ниже).

```json
{
  "sender": "approver@example.com",
  "mailbox": "INBOX",
  "project_mailbox": false,
  "parent_mailboxes": ["INBOX"],
  "attachment_senders": [],
  "amount_cells": {},
  "disk_folders": {}
}
```

Заменить sender реальным адресом в Railway. mailbox — точный путь папки согласований, parent_mailboxes — папки исходных писем. Кириллица преобразуется в IMAP modified UTF-7 автоматически. Пустой attachment_senders допускает любого отправителя точного исходного письма; заполните список проверенными адресами, если нужен дополнительный фильтр.

amount_cells задаётся по ключу «акт:253» или «смета:337», например {"sheet":"Лист1","cell":"J50"}. Ячейка — пример, обязательно сверить с документом. Без настройки сумма неизвестна.

Тест в настроенной теме:

```
/status
/report 2026-10-01 2026-10-23
```

/report отправляет сводку без записи на Диск. Повтор одинаковой сводки блокируется SQLite. Если доставка неопределённа (pending), проверить Telegram вручную до повторного запуска. Прерванные команды автоматически не повторяются. Для каждого запуска сейчас сохраняется последний report.json/report.txt и вложения на Volume.

## Локальный запуск

```sh
pip install -r requirements.txt
cp config.example.json config.json
python bot.py --start 2026-10-01 --end 2026-10-23
python -m unittest discover -s tests -v
```

Офлайн: добавить --eml-dir /path/to/eml. Для проверки связей включить исходные письма, даже если они до начала периода. Секреты задаются переменными окружения; .env автоматически не загружается.

Без --publish внешних записей нет. --publish отправляет отчёт в настроенную тему и загружает документы с заданным disk_folders на Диск; --no-disk отключает загрузку. Для Диска нужен YANDEX_DISK_TOKEN. Папки должны существовать: бот их не создаёт и не угадывает. Иной существующий файл не перезаписывается.

## Ограничения пилота

Нет ежедневного планировщика, распознавания PDF/XLS/сканов, универсального поиска итоговой суммы, обработки отзыва согласования и выбора последней версии за пределами периода. Это сводка событий согласования, не окончательный финансовый статус и не подтверждение оплаты. Проверить регэкспы и фильтр проекта на фактической переписке. Суммы, отмеченные неизвестными, не входят в сумму известных значений. Согласования без распознанного маркера проекта из общей папки пропускаются.

Номер/тип файла проверяются по имени. Формулы Excel не исполняются, используется кеш. Для обработки вложений установить ограничения памяти/CPU и срок хранения данных. Не публиковать реальные письма, отчёты, конфигурацию с адресами или секреты в Git.
